# 02 — The Request / Response Cycle

Every FastAPI request follows the same pipeline. If you can hold this
picture in your head, debugging gets *much* easier.

```
Client ─▶ uvicorn (ASGI) ─▶ Middleware A ─▶ Middleware B ─▶ Deps ─▶ Handler
                                                                       │
Client ◀── Middleware A ◀── Middleware B ◀── Serialize (Pydantic) ◀────┘
```

Things to internalize:

- **Middleware is an onion.** The first one added is the *outermost*.
- The *outermost* sees the request first and the response last.
- Each middleware can mutate request / response.
- Exceptions raised inside the handler bubble up *through* the middleware
  layers (chapter 7 covers exception handlers).

## Run

```bash
uvicorn 02_request_response_cycle.app:app --reload --port 8000
curl -v http://localhost:8000/
```

Look at the response headers:

- `X-Request-ID` — generated by middleware A.
- `X-Process-Time-ms` — total handler latency.
- `X-Stage: middleware-B-visited` — proof that B ran.

And in the terminal you will see logs in this order:

```
[A in ]  GET / id=...
  [B in ] before handler
    [handler] running
  [B out] after handler
[A out]  GET / took=...ms
```

## Why this matters

Real-world middleware in production:

- **Request ID / correlation ID** — match logs across services.
- **Authentication** — reject unauthenticated requests early.
- **CORS** — let browsers talk to your API.
- **Compression** — gzip / brotli responses.
- **Metrics / tracing** — Prometheus, OpenTelemetry.
- **Rate limiting** — chapter 18.

## Edge cases

- A middleware that forgets to call `await call_next(request)` will
  **hang the request**.
- A middleware that raises will skip everything below it.
- `request.state` is per-request; do not store globals there.

## Exercises

1. Swap the order of `add_middleware` calls. Watch the log order flip.
2. Add a third middleware that strips `X-Internal-*` headers from the
   request before they reach the handler.
3. Have the handler raise `RuntimeError("boom")`. Where in the log do you
   see the error? Notice that `X-Process-Time-ms` is *still* set —
   because middleware A wraps the whole pipeline.
